# 최종 검토 결과

지정하신 네 파일의 변경 부분만 읽었습니다. 빌드와 테스트는 실행하지 않았으므로 아래 내용은 모두 코드를 읽고 내린 판단입니다. 남은 결함은 두 가지이며, 둘 다 P2입니다.

## 새로 남은 결함

**1. TextField: 글자가 칸보다 길어지면 끝에 있는 커서가 보이지 않음 (P2)** (`Fields.kt:182-211`)
- 실제 실행 경로:
  1. 텍스트가 칸보다 길어지면 커서를 맞추는 LaunchedEffect(`Fields.kt:96-109`)가 `right = cursor.right + 4`까지 스크롤하려고 합니다.
  2. 그런데 `scrollTo`는 `maxValue`(텍스트 폭에서 화면 폭을 뺀 값)를 넘지 못하므로, 화면 오른쪽 끝이 텍스트 끝에 딱 맞춰집니다.
  3. 커서는 `drawRect(rect.left, ...)`로 그려지는데, 끝 위치에서는 `rect.left`가 텍스트 폭과 같습니다. 그래서 커서 3px가 콘텐츠 밖, 즉 화면 밖에 그려집니다.
  4. 이 부분은 `horizontalScroll`의 clip이 잘라내므로 커서가 사라집니다.
- 기본 커서는 x 좌표를 `size.width - cursorWidth/2` 이하로 제한하지만, 직접 그리는 커서에는 이 처리가 없습니다.
- 가장 흔한 상황인 "끝에 이어서 입력하기"(URL, 이메일 등)에서 생기는 문제입니다.
- 수정안: 안쪽 Box를 `Modifier.widthIn(min = viewport).drawWithContent { ... }.padding(end = cursorWidth)`처럼 바꾸어, 커서가 들어갈 자리를 콘텐츠 폭에 포함하십시오.
  - 오른쪽에만 패딩을 주므로 탭 위치 계산(`localPositionOf`)에는 영향이 없습니다.
  - 기존 `+4` 보정도 이제 실제로 효과를 냅니다.
  - 더 간단한 방법은 x 좌표를 `rect.left.coerceAtMost(size.width - cursorWidth)`로 제한하는 것입니다. 다만 이 경우 커서가 마지막 글자에 겹칩니다.

**2. NumberField: 키보드를 닫은 뒤 칸을 눌러도 다시 열리지 않음 (P2)** (`Fields.kt:428-436`)
- 실제 실행 경로:
  1. 칸을 탭하면 칸의 `clickable`이 Main pass에서 down 이벤트를 먼저 소비합니다.
  2. 그래서 BasicTextField의 탭 처리(decorationBox 바깥의 `tapToFocus`, 포커스 상태라면 `keyboardController.show()`)는 이벤트를 받지 못합니다.
  3. 이미 포커스가 있는 상태라면 `requester.requestFocus()`는 아무 일도 하지 않습니다.
- 결과적으로 처음 탭할 때는 포커스를 얻으면서 입력이 시작되어 키보드가 뜹니다. 하지만 Back으로 키보드를 닫은 뒤에는 칸을 눌러도 키보드가 다시 뜨지 않습니다.
- 수정안: `LocalSoftwareKeyboardController.current`를 받아 두고, 클릭 블록에서 `requestFocus()` 다음에 `keyboard?.show()`를 호출하십시오.

**참고 (의도 확인 필요):** 같은 클릭 경로에서 커서는 `TextRange(i)`, 즉 선택 없이 i 위치에 놓입니다.
- 그런데 강조 표시는 i번째 칸에 됩니다. 그래서 사용자는 그 칸을 덮어쓴다고 예상하게 됩니다.
- 실제로는 숫자가 끼워 넣어지고, `take(digitCount)` 때문에 마지막 숫자가 버려집니다.
- 덮어쓰기가 의도라면 `i < value.length`일 때 `TextRange(i, i + 1)`로 선택하고, 강조 표시 기준을 `selection.start`로 바꾸십시오.

## P1/P2 결함이 없다고 본 부분

- **actionModifier:**
  - `focusProperties { canFocus = false }`는 바로 다음 focus target인 clickable 내부 target에만 적용됩니다.
  - 키 이벤트는 focusable target과 그 상위에서만 처리되므로, clickable이 Enter를 한 번 더 처리하는 경로는 없습니다.
  - loading(`blocked`) 중에는 포커스가 유지되고 키는 소비만 되며, 실행은 막힙니다.
- **shadow 캐시:** `layers`는 data class List라서 equals로 비교되므로, `remember` 키가 매번 바뀌지 않습니다. density가 바뀌면 `drawWithCache`가 캐시를 무효화합니다.
- **Wheel:**
  - 호스트가 값을 늦게 반영해도 `pendingRequest`가 남아 있다가 `LaunchedEffect(index)`에서 `onSettled`가 정확히 한 번 호출됩니다. 지연 확정과 겹쳐 두 번 호출되는 경로는 없습니다.
  - 행에는 이제 `detectTapGestures`만 있어 포커스 정지점이 되지 않습니다.
  - 포커스를 잃으면 편집 모드가 해제되고, 끝에 닿았을 때도 키를 소비합니다.
  - 큰 fontScale에서도 행 높이, 패널 높이, contentPadding이 서로 맞게 늘어납니다.
- **Dropdown:**
  - 앵커 좌표는 화면 좌표로 바꾼 뒤 Dialog Box의 화면 원점을 빼서 계산합니다.
  - 메뉴 영역(`boundsInParent`)과 탭 좌표는 같은 Box 좌표계를 씁니다.
  - IME를 포함한 safe inset이 위치, 폭, 최대 높이에 일관되게 반영됩니다.
  - 열린 직후 첫 프레임에는 `dialogOrigin`과 `menuSize`가 0이라 위치가 잠깐 어긋날 수 있습니다. 다음 프레임에 바로잡히므로 기능 결함으로 보지 않았습니다.

위 1번과 2번은 계측 테스트로 확인할 것을 권합니다.
- 1번: 긴 문자열을 입력한 뒤 커서 픽셀을 캡처해 보십시오.
- 2번: IME를 숨긴 뒤 칸을 탭하고 `isImeVisible`를 확인해 보십시오.
